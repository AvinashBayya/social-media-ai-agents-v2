# Sentinel AI

OSINT analysis and monitoring platform built for **ADITI 4.0 / iDEX Problem Statement 18**,
sponsored by the Indian Air Force.

> **Status: prototype / demonstrator.** Not an accredited system. Several modules are
> deliberately unimplemented and say so in the UI rather than showing placeholder output.
> See `CLAUDE.md` for the current capability breakdown.

## Stack

- TanStack Start 1.168 (SSR), React 19, TypeScript, Vite 8, Bun
- Tailwind 4, shadcn/ui
- 28 routes under `src/routes/`, i18n across 15 Indian languages
- Deployed to Azure Container Apps (Central India) as a Node server container

## Modules

| PS-18 module                                 | State                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------- |
| 1 · Source credibility, user-defined factors | Implemented — six analyst-weighted factors, per-factor explanation    |
| 2 · Open-source content analysis             | Implemented — summarisation and entity extraction over live feeds     |
| 3 · Social media analysis                    | Not implemented                                                       |
| 4 · Image / video, deepfake detection        | Not implemented                                                       |
| 5 · Reports and GIS                          | Partial — reports generated by the LLM; per-event geocoding not built |

## LLM

Open-weight models only, behind an OpenAI-compatible interface so the endpoint is
configuration rather than code:

```sh
LLM_BASE_URL=https://api.sarvam.ai/v1
LLM_API_KEY=<key>
LLM_MODEL=sarvam-105b
LLM_FALLBACK_BASE_URL=https://api.groq.com/openai/v1
LLM_FALLBACK_KEY=<key>
LLM_FALLBACK_MODEL=openai/gpt-oss-120b
```

Both models are Apache 2.0 and self-hostable; pointing `LLM_BASE_URL` at a vLLM instance
requires no code change. No Llama-derived model is used — Meta's Acceptable Use Policy
bars military and espionage use.

## Development

Requires [Bun](https://bun.sh) and Node 24.

```sh
bun install
bun run dev      # dev server
bun run build    # production build to .output/
bun run lint
```

Copy the LLM variables above into `.env` (gitignored) before running. Without them the AI
features report "AI unavailable" rather than returning fabricated output.

## Container

```sh
docker build -t sentinel-web .
docker run -p 3000:3000 --env-file .env sentinel-web
```

The image builds with Bun and runs on `node:22-alpine`, serving `.output/server/index.mjs`
on port 3000.
